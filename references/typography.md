# Typography

Use one intentional sans-serif family by default. A second family requires a clear role and a recorded reason. Type should make hierarchy and reading order obvious before decoration does.

## Type roles

| Role | Default size | Line height | Use |
| --- | ---: | ---: | --- |
| Display | 48–64 | 1.05–1.1 | Landing-page statement or product moment; use sparingly |
| Heading 1 | 34–40 | 1.1–1.2 | Page title |
| Heading 2 | 24–28 | 1.15–1.25 | Major section |
| Heading 3 | 18–20 | 1.2–1.3 | Subsection or panel title |
| Body | 16 | 1.45–1.6 | Default reading text |
| Body small | 14 | 1.4–1.5 | Supporting copy and dense utility |
| Label | 12–14 | 1.25–1.4 | Control label, metadata, status |
| Code or data | 13–14 | 1.4–1.5 | Structured values; use only when useful |

These are starting ranges, not a rigid scale. The final `DESIGN.md` should list exact values and weights for the selected family.

## Rules

- Use weight to express hierarchy before using size extremes or color.
- Keep body text at a comfortable reading size and measure.
- Avoid all-caps for long labels and paragraphs. Use it only for short, secondary metadata when it improves scanning.
- Use sentence case for controls, navigation, and most headings.
- Give text enough line height and width. Do not center long reading content.
- Let text wrap. Do not solve every variation by shrinking type.
- Keep labels stable across screens. If a control says `Create`, do not rename it `Add` elsewhere without a product reason.
- Pair icons with text when the meaning is not universally understood.
- Test long words, localization expansion, large text, and zoom.
- Do not use placeholder copy in an accepted screen reference.

## Content width

Use a reading measure of roughly 45–75 characters per line for prose. Wider application surfaces may use more width for tables, timelines, and comparison tasks, but keep text columns readable.

## Type acceptance

- Every role has a name, size, weight, line height, and color role.
- Heading order reflects information hierarchy.
- Text remains readable in light and dark themes.
- Focus, link, error, disabled, and selected styles are defined.
- The design does not depend on tiny text or low-contrast metadata to fit.
