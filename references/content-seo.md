# Content and SEO

Use this reference for public pages, landing pages, onboarding copy, and product text that helps people find or understand the product. SEO supports useful content; it does not replace product clarity.

## Page content contract

For every public page, define:

| Field | Requirement |
| --- | --- |
| Search intent | The problem or question the page answers |
| Audience | Who the page is for and what they already know |
| Page purpose | One action or understanding goal |
| URL | Descriptive, stable, readable, and aligned with the page |
| Title | Unique, descriptive, concise, and written for the page |
| Description | A useful, specific summary that earns the click without making a false promise |
| H1 | One clear page promise or topic |
| Headings | Ordered sections that make the page scannable |
| Internal links | Descriptive link text that names the destination |
| Media | Useful alt text or an explicit decorative treatment |
| Structured data | Only when the page type supports it and the data is complete and visible |
| Proof | Specific evidence, source, customer, or mechanism; no invented claims |
| CTA | One primary next step, with a clear result |

## Writing rules

- Write for people first. Use the words a real audience uses, but do not force exact phrases into every sentence.
- Make the first sentence or heading useful without hype.
- Prefer concrete nouns and active verbs.
- State what the product does, for whom, and why it matters.
- Use short paragraphs, meaningful headings, and scannable lists where they improve comprehension.
- Use one idea per sentence when the information is important.
- Keep product labels consistent across page copy and UI.
- Explain unfamiliar terms before using them repeatedly.
- Do not use fake urgency, empty superlatives, or vague claims such as "the future of" without evidence.
- Do not hide essential information behind a graphic or animation.

## Landing-page section defaults

Choose only the sections the product needs. A strong default is:

1. Navigation and clear entry point.
2. Hero with one promise, supporting sentence, and primary action.
3. Product proof or direct product view.
4. Three or fewer use cases or benefits tied to user problems.
5. How it works or a credible explanation.
6. Evidence: customer, result, source, or transparent limitation.
7. Pricing or plan choice when relevant.
8. FAQ for real objections.
9. Final CTA and footer.

Avoid repeating the same promise in every section. Give each section a job.

## Search hygiene

- Use one unique title and description per indexable page.
- Avoid vague titles such as `Home` or repeated brand-only titles.
- Do not stuff keywords into titles, headings, URLs, or body copy.
- Use descriptive URLs and link text.
- Add internal links where they help users understand the topic or next step.
- Keep the page's visible content aligned with its metadata.
- Use structured data only for information visible on the page. Prefer complete, accurate data over many incomplete types.
- Add useful alternative text to meaningful images. Do not describe decorative pixels.
- Do not promise rankings. Record the intent, content decision, and measurement plan instead.

## Product UI copy

SEO does not govern authenticated product surfaces. For product UI, prioritize:

- Clear action labels.
- Short, specific errors.
- Helpful empty states.
- Honest loading and progress text.
- Consistent nouns and verbs.
- A next action after success.
