# Anti-slop review

Use this as a rejection list, not as a style generator. A design can be simple, expressive, or ornate when the product earns it. It must still have a reason.

## Reject by default

- Random gradients, glows, grain, glass, or shadows with no product role.
- Oversized hero text that says little.
- Cards around every sentence or list item.
- Pills used for ordinary labels, navigation, or unrelated actions.
- Emoji or decorative symbols used as the primary icon system.
- Unlabeled icon-only actions when the meaning is not universal.
- Multiple accents competing for attention.
- Arbitrary corner radii, border weights, or type sizes.
- Placeholder copy, repeated generic slogans, or lorem text in accepted references.
- Fake metrics, fake testimonials, fake logos, or unverified proof.
- UI text that does not match the product's nouns and verbs.
- Navigation that exists because a screenshot convention suggested it.
- Empty space filled with decoration instead of hierarchy.
- A single polished state with no loading, empty, error, disabled, or success treatment.
- Mobile screens that are only narrow desktop screens.
- Image-generated letters, logos, charts, or controls treated as final assets.
- A visual reference that contradicts `DESIGN.md`.

## Positive replacement

When rejecting a pattern, replace it with:

1. A clear content hierarchy.
2. A semantic token.
3. A familiar component.
4. Real state coverage.
5. Useful copy and a next action.
6. A restrained visual treatment that supports the task.

## Review questions

- What is the product-specific reason for this visual choice?
- Would the screen still work if decoration were removed?
- Does the choice improve recognition, trust, speed, or comprehension?
- Is it consistent with the brand kit and token table?
- Does it survive both themes, compact screens, and varied content?
